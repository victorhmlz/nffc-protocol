## KNOWN ISSUES

1. **Local Node is 22.8.0 — too old for the current toolchain.** Node gained stable `require(esm)`
   only in 22.12 / 20.19. Under 22.8.0, Vite ≥ 7 and jsdom ≥ 26 (both ESM-only) crash Vitest's
   config loader and jsdom's encoding sniffer with `ERR_REQUIRE_ESM`. **Mitigation:**
   `pnpm-workspace.yaml` `overrides` pin `vite@6.4.3` and `jsdom@25.0.1` — both run on old *and*
   current Node, so CI (which uses a current 22.x via `.nvmrc`) is unaffected and the lockfile is
   consistent everywhere. **Recommendation for the Project Lead:** bump local Node to the current
   22.x LTS (`nvm install 22 && nvm use 22`), then delete the two overrides and let Vitest/jsdom
   float to latest. `nvm` did not respond in this non-interactive environment, so the bump is left
   to the Project Lead. `engines.node` is set to `>=20.9.0` (Next 16's floor) rather than `>=22.12`
   to avoid blocking install on the current local Node; tighten it after the bump.
2. **Global Corepack was updated** `0.29.3` → `0.36.0` (`npm i -g corepack@latest`) — a user-level
   change outside the repo — because the Node-bundled Corepack failed pnpm activation with
   `Cannot find matching keyid` (stale signing keys). Corepack 0.36 emits an `EBADENGINE` warning
   (wants Node ≥ 22.22) but works. Revert with `npm i -g corepack@0.29.3` if desired; the project
   only relies on `packageManager` in `package.json`, which any recent Corepack honors.
3. **Vitest prints** `The CJS build of Vite's Node API is deprecated` — a harmless warning from
   running the Vite 6 CJS entry under Vitest 3; disappears once override #1 is removed.
4. **`create-next-app` also generated `AGENTS.md` + `CLAUDE.md`.** `AGENTS.md` carries a block that
   `next dev` re-writes, so it is committed to keep the tree clean. These are Next.js-generic; a
   project-specific `AGENTS.md`/`CLAUDE.md` can replace them in a later TASK.
5. **README links to `docs/spec/` and `docs/reports/`** which exist on `main` only after PR #1
   (TASK-00) merges. This branch is cut from `main` @ `18f6689`. Merging PR #1 before this PR
   resolves the links; the two PRs touch disjoint paths and do not conflict.
6. **`@vitejs/plugin-react` was intentionally dropped.** Vitest transforms `.tsx` via esbuild with
   the automatic JSX runtime (`tsconfig` `"jsx": "react-jsx"`); the smoke render test passes without
   the plugin. Add it in TASK-03 if Fast-Refresh-style component testing is wanted.
